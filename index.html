How · 关键技术判断

为什么「迁移」在技术上成立

🧬

存储高度同质

实测本机 8 款客户端：主流产品几乎全部采用「JSONL 事件日志 + 可选 SQLite 索引」的同一范式。差异只在信封字段和索引表——适配器模式即可抹平。

✉️

领慧 = Claude + 信封

实测发现领慧的存储就是 Claude Agent SDK 事件流外包一层 {type, sessionId, timestamp, data} 信封。互转只需解包/打包——这是 M0 能用 3 天闭环的原因。

🛡️

写回安全第一

迁移的最大风险是写坏目标客户端。我们的铁律：写前备份（含 WAL 边车文件）、事务包裹、目标进程运行中拒写、schema 指纹探测未知版本自动降级只读。

工程经验来自两个被验证十年的社区：SillyTavern 生态的跨平台对话迁移实践（版本化格式 + extensions 命名空间 + 原子写三件套），以及 OpenAI Responses API 的 items 消息模型（消息/工具调用/工具输出同为一等公民）——IR v1 是两者与本地实测的结合。
